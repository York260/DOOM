# v2-05　開發計畫

## 1. 範疇對照

| 項目 | v1 | v2 |
|---|---|---|
| 地圖 | 3.5 km² 開放世界 | 校園六區（約 600 m × 600 m）＋三個遠征地點 |
| 視角 | 第三人稱 | 斜 45 度俯視角 |

## 2. 技術選型

| 需求 | 建議 |
|---|---|
| 引擎 | **Unity 6**（URP）。俯視角合作生存遊戲常用，Steam、Switch、手機都容易移植 |
| 大量蟲群 | Entities／Burst（ECS）＋ GPU 實例化，目標 600 隻同屏 60 fps |
| 連線 | Netcode for GameObjects ＋ Steam 好友連線（主機－客戶端） |
| 異能 | 資料驅動：本源、條件、頓悟形態、共鳴表都寫在資料表裡，設計師不用改程式就能新增 |
| 條件偵測 | 每種條件一個「接近度函數」（0–1），同時驅動共鳴光和頓悟判定 |
| 種子 | 一個主種子分成多條獨立的亂數串流（異能、天氣、事件、夥伴），方便「每週同一天」 |
| 生存日誌 | 事件記錄 ＋ 模板文法組合句子；不需要即時網路 |

> 如果團隊熟悉 Unreal，也可以用 UE5（Mass Entity 處理蟲群），其他設計不變。

| 里程碑 | 月份 | 要證明的事 | 驗收標準 |

## 6. KPI

| 指標 | 目標 |
|---|---|
| 第一次頓悟的時間（中位數） | 交融波後 5 分鐘內 |
| 每輪平均發現的條件數 | 2 個以上（三個全中的比例約 25%） |
| 覺醒（第四條件）的比例 | 約 5–10% 的輪 |
| 第一輪的平均存活 | 第二～三夜 |
| 「再來一輪」的比例 | 70% 以上 |
| 第二輪前夜使用記憶的比例 | 80% 以上 |
| 600 隻蟲同屏 | 60 fps（中階 PC） |

## 7. 風險

| 風險 | 對策 |
|---|---|
| 共鳴光太好找，失去發現的樂趣 | 光只表示「接近」，不表示是什麼；第四條件不發光；接近度函數可以調整 |
| 共鳴光太難懂，玩家不知道為什麼變亮 | 第一輪的演習流程會「剛好」帶玩家經過一個條件；生存日誌會記下「你剛剛在 ___ 附近，按鈕亮了」 |
| 記憶讓後面的輪太簡單 | 記憶的可靠度隨天數降低；異能每輪重抽；夜晚威脅順序隨機 |
| 七天太長，朋友約不到 | 每天早上自動存檔；三夜模式 |
| 自動攻擊讓戰鬥太無聊 | 戰鬥的決策放在走位、異能時機、共鳴與防線；PC 可以開手動瞄準 |
| 和《Survival Log》太像 | 主題、核心爽點（異能）、合作與動作戰鬥都不同（見 `00` §9） |
