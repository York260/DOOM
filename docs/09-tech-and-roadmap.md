# 09　技術架構與執行計畫

## 1. 引擎選型

| 需求 | Unreal Engine 5 | Unity 6 | Godot 4 |
|---|---|---|---|
| 開放世界串流 | World Partition，成熟 | 需要自建或購買外掛 | 偏弱 |
| 上千隻蟲同屏 | **Mass Entity**＋頂點動畫貼圖（VAT）＋Niagara | DOTS／ECS，效能很好，但學習曲線陡 | 需要大量自製 |
| 模組化異能 | **Gameplay Ability System（GAS）**：以標籤和事件組合技能，非常適合「六元件」 | 需自建 | 需自建 |
| 多人連線 | 內建複製（Replication）＋Iris；GAS 有預測機制 | Netcode for GameObjects／Entities | 基本可用 |
| 動態音效 | MetaSounds | FMOD／Wwise | 基本 |
| 寫實畫面 | Lumen、Nanite | HDRP | 偏弱 |
| 小團隊的痛點 | 編譯時間長、C++ 門檻 | — | — |

**結論**：**Unreal Engine 5**（⚙ 依 Q1）。GAS 與 Mass 兩項系統正好對應本作的兩大技術核心：模組化的異能，以及大規模的蟲群。

## 3. 關鍵系統的技術要點

### 3.1 時間線服務（種子）

- 一個主種子衍生出**多條獨立的 RNG 串流**：世界、天氣、事件、NPC、每位玩家的異能、群思。
- 串流互相獨立。這樣「同種子挑戰」時，玩家的不同行為只會影響事件串流，不會改變每個人的異能，讓比較公平。
- 種子編碼為人類可讀的時間線編號，例如 `#0742-1A3F`。

### 3.2 異能組裝器

- 六元件以 **DataAsset** 定義：本源、顯化、鑰、代價、徵兆、真名，以及相容表。
- 組裝結果是一組 GAS 的 GameplayAbility 與 GameplayEffect，以 GameplayTag 標示物理標籤（用來判斷共鳴）。
- **鑰匙監聽器**：每一種鑰匙類別都是一個監聽元件，監聽移動狀態、肢體輪盤、壓力值、環境體積（雨、黑暗、水中）、生理數值、物品持有、語音輸入（選配）。
- **除錯工具**：開發版可以顯示某位玩家的隱藏異能、強制觸發鑰匙、模擬提示階梯。

### 3.3 群思與蟲群

- **Mass Entity**：近距離的蟲以完整的實體模擬；中距離的蟲以簡化的模擬；遠距離的蟲以「蟲雲」抽象模擬（只計算數量與移動方向）。
- **流場尋路**：大群移動使用流場，個體在最後一段距離才切換成局部避障。
- **渲染**：頂點動畫貼圖（VAT）＋GPU 實例化，目標是 1500 隻同屏時維持 60 fps（中階 GPU，1080p）。
- **網路**：蟲的狀態以「群組」為單位複製，客戶端以插值補足個體動作；只有與玩家近距離互動的個體才完整複製。
- **戰術帳本**：伺服器端統計，每個繁殖週期結算一次。

### 3.4 命運織機

- **張力模型**：參考 AI Director 的「強度」數值，輸入包括玩家的生命、壓力、近期傷害、彈藥、隊伍分散程度。
- **事件調度**：Storylet 架構（品質導向敘事），事件以資料表定義前置條件、權重、冷卻、參與者槽位。
- **戲劇鉤子**：以規則引擎偵測（見 `05` §2.3）。
- **工具**：視覺化的事件編輯器（節點圖），以及「時間線重播器」：用同一個種子加上錄下的玩家輸入，可以重現任何一局，方便除錯與平衡。

### 3.5 事蹟記錄器與結算報告

- **事蹟記錄器**：語意事件日誌，格式為「誰、做了什麼、對誰、在哪裡、什麼時候、情緒權重、標籤」。每局約 500–2000 筆。
- **報告生成器**：
  1. **評分**：依 `07` §2 的公式計算。
  2. **稱號**：依規則表生成。
  3. **文字**：以中文模板文法（類似 Tracery 的規則展開）組合評語、蟲族評價與後續。每種文字都有上百個片段，並依旗標選擇。
  4. **選配 LLM 潤飾**：把模板輸出與事蹟清單交給大型語言模型（例如 Claude API）潤飾。規則如下：
     - 提示中只能放入事蹟記錄器的事實，並要求「不得新增事實」；
     - 輸出後以事實核對器比對人名、時間與事件，不通過就退回模板版本；
     - 網路斷線或關閉此功能時，一律使用模板版本；
     - 結果快取在存檔中，同一局不會重複生成。

### 3.6 代價的感知改寫

- 代價直接作用在**客戶端的後製與介面層**：去色、模糊名牌、刪除地圖標記、靜音（音訊匯流排）、畫面結霜。
- 必須保證這些效果不會影響其他玩家的畫面（除了「電子」代價會刻意影響隊友的無線電）。

### 3.7 語音

- 使用 EOS Voice 或 Vivox：近距語音＋無線電頻道（加上濾波器與雜訊）。
- **聲紋偵測**：在客戶端計算麥克風音量的包絡，超過閾值時送出「噪音事件」給伺服器（只送音量等級，**不送出任何語音內容**），保護隱私。

## 9. 風險與對策

| 風險 | 機率 | 影響 | 對策 |
|---|---|---|---|
| 知識鎖讓玩家挫折、覺得「不知道要幹嘛」 | 高 | 高 | 提示階梯、提示強度選項、紙上原型提早驗證、導演安排自然觸發的情境 |
| 程序生成的異能難以平衡 | 高 | 中 | 威力預算制、自動化機器人大量測試、遙測儀表板 |
| 大量蟲群的效能與網路同步 | 中 | 高 | M0 技術預研、蟲雲的分級模擬、以群組為單位複製 |
| 開放世界的範疇失控 | 高 | 高 | 校園優先、雲台鎮可降級為遠征地圖（Q1 選項 A）、內容分級（必要／加分／夢想） |
| 隨機性破壞戲劇性 | 中 | 中 | 骨與磚架構、導演的戲劇鉤子、手工寫成的必然節點 |
| 以真實學校為藍本引發爭議 | 低 | 中 | 去識別化原則（見 `01` §2.1）；不出現真實校名、校徽、人物；內容不貶低警察職業 |
| 蟲族題材讓部分玩家不適 | 中 | 中 | 蟲恐懼友善模式、血腥程度選項 |
| LLM 潤飾的成本、延遲與內容風險 | 中 | 低 | 選配功能、模板版本永遠可用、事實核對器、快取 |
| 語音偵測的隱私疑慮 | 低 | 中 | 只傳送音量等級，不傳送內容；預設關閉 |
| 中文文字量龐大、在地化困難 | 中 | 中 | 模板文法設計時就考慮多語言；文字庫獨立管理 |

## 10. 範疇分級：必要、加分、夢想
