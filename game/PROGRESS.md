# 《熄燈號之後》遊戲開發進度

> 這份檔案是開發的唯一進度來源。每天的自動接續（排程）會先讀這裡，從第一個未完成的項目往下做。
> 設計依據：`docs/v2/`。技術：Vite ＋ TypeScript ＋ Three.js，網頁版（手機與電腦都能玩）。

## 怎麼跑

```bash
cd game
npm install
npm run dev        # 開發伺服器
npm run build      # 產出 dist/index.html（單一檔案）與 dist/artifact.html（給 Claude artifact 發布用）
```

測試（需要全域安裝的 Playwright）：

```bash
NODE_PATH=$(npm root -g) node tests/smoke.mjs            # 單人：完整一輪
# 連線：先開一個本機 PeerJS 配對伺服器（npm i peer；PeerServer({port:9000, host:"127.0.0.1", path:"/"})）
NODE_PATH=$(npm root -g) PEER=127.0.0.1:9000 node tests/coop.mjs
NODE_PATH=$(npm root -g) node tests/perf.mjs              # 300 隻蟲：模擬時間、draw call、三角形數
NODE_PATH=$(npm root -g) node tests/balance.mjs 4 2 3     # 平衡機器人：局數、救回人數、三夜／七夜
```

遊戲網址加上 `?peer=主機:埠` 可以改用自己的配對伺服器（預設用 PeerJS 的公用伺服器）。

## 平衡數據

`tests/balance.mjs` 的機器人會守最忙的門、常按異能、修門，白天只帶回少量物資（材 +6、糧 +2、電 +1），而且幾乎不會刻意去找異能條件。它是「普通但不太會玩」的基準線。

| 情況 | 第一、二夜 | Boss 夜 |
|---|---|---|
| 三夜、救回 0 人 | 門會破、避難室受一點傷 | 4 局贏 1 局 |
| 三夜、救回 2 人 | 門剩一半左右 | 4 局贏 2 局（輸的兩局只找到 0–1 個條件） |
| 三夜、救回 3 人 | 門剩一半左右 | 4 局贏 1–2 局 |
| 七夜、救回 3 人 | 第四夜起門會破、第六夜避難室會掉血 | 2 局贏 0 局（困難模式） |

主要調整：避難室 520→800 血、蟲咬避難室的傷害 ×0.6、避難室被攻擊時警告＋紅色箭頭；Boss 打避難室 22→9／秒、蓄力時受到雙倍傷害（並提示）、太大進不了門，改成「破門後把觸手伸進來」；據點裡每多一個人，夜晚的蟲多 10%；守衛傷害 8→6；三夜 Boss 血量 2600→2200；七夜模式第三夜起多第四波、第四夜起混入第二種威脅。

## 效能數據

`tests/perf.mjs`（桌機 CPU、軟體繪圖）：318 隻蟲時，每步模擬中位數 0.8 ms、95 百分位 3.2 ms；62 個 draw call、約 2.6 萬個三角形；沒有陰影貼圖。手機上：高密度螢幕關閉 MSAA，像素比上限 1.75，開局 3 秒後若平均每幀超過 22 ms，就逐步降低解析度（最低 0.75）。HUD 只在數值改變時才寫入畫面。
